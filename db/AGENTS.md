# AGENTS.md

Local guidance for the database workspace in `db/`. Read [../AGENTS.md](../AGENTS.md) first for monorepo-wide rules.

## Scope

- Applies to Drizzle ORM schemas, migrations, and seed scripts under `db/`.
- Source of truth is live code in `db/`, especially [schema/](schema), [drizzle.config.ts](drizzle.config.ts), and [scripts/](scripts).

## Database Schema

- All schemas live in `db/schema/` and are exported from `db/schema/index.ts`.
- Use Drizzle ORM's `pgTable` for PostgreSQL tables.
- Follow the existing naming conventions: singular table names (e.g., `user`, `session`, not `users`, `sessions`).
- Use prefixed CUID2 primary keys via `generateAuthId` / `generateId` in [schema/id.ts](schema/id.ts) (for example `usr_…`). Do not use a bare `cuid()` helper as the table ID pattern.
- Timestamps should use `createdAt` and `updatedAt` columns with `defaultNow()`.

## Migrations

- Migrations are generated by Drizzle Kit and stored in `db/migrations/`.
- **Never hand-edit migration files.** If a migration is incorrect, delete it and regenerate.
- One feature = one migration. Do not accumulate multiple schema changes across commits.
- Migration files are named with timestamps: `YYYY-MM-DD-THH-MM-SS-<name>.sql`.
- After changing schemas, run `bun db:generate` from the repo root.

## Seeds and Exports

- Seed scripts live in `db/scripts/seed.ts` and populate the database with initial data.
- Export scripts live in `db/scripts/export.ts` and dump database state for debugging.
- These scripts are invoked via `bun db:seed` and `bun db:export` from the repo root.

## Environment

- `DATABASE_URL` is loaded from the repo root `.env` file.
- Migrations and seeds run directly against PostgreSQL; there is no intermediate ORM layer.

## Anti-patterns

- Hand-writing SQL migration files instead of using Drizzle Kit to generate them.
- Editing migration files after they've been generated.
- Accumulating multiple schema changes in a single migration.
- Using `db:push` for anything other than disposable local iteration.
- Bypassing the migration workflow to apply schema changes directly to production.

## Review Priorities

- Verify that schema changes are accompanied by migrations.
- Ensure migrations are reversible or idempotent where possible.
- Check that seed scripts do not hardcode environment-specific values.
- Confirm that export scripts do not leak sensitive data.

## Commands

See the [root README](../README.md) for the canonical command reference.

From inside `db/`:

```bash
bun generate             # Generate migrations
bun migrate              # Apply migrations
bun studio               # Launch Drizzle Studio
bun seed                 # Run seed scripts
bun export               # Export database state
bun check                # Check migration status
bun typecheck            # Typecheck db code
```
